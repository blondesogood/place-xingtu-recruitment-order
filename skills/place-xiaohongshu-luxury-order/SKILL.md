# 小红书二奢图文

## 两个能力

- `ORDER`：绑定用户明确给出的完整订单集合，逐单查询、防重、创建并回填，返回待接单或待支付等结果。
- `PAYMENT`：只读取已保存的授权批次或其中指定子集，逐单检查接单、核价、付款及对账。没有内部任务映射时返回对应原因，不创建合作，也不补回填。

正常流程由程序核验后直接执行，不要求用户确认金额、确认付款或回复“继续”。用户通知与外部自动化调用使用同一支付入口。等待接单是本轮结果，不在 Skill 内后台等待；调用时机由调用方管理。

## 启动与运行

1. 完整读取 `$ego-browser`，按[标准入口](references/standard-entry.md)调用 `runStandard(input, adapter)`。当前核验环境是 Codex、macOS、Ego Lite。
2. 读取[发行声明](references/release.json)、[业务规则](references/business-rules.v2026-09-11-r1.json)及[运行契约](references/runtime-contract.md)。按[网页流程](references/workflow.md)执行；使用标准适配器，不能临时替换最终按钮或伪造平台事实。
3. 下单首次使用稳定、唯一的 `taskId` 和用户原始订单集合。后续同一批保持该集合；新的授权批次使用新的 `taskId`。保存返回的 `batchRef`。支付以该引用限定原授权范围，无需原对话中的付款事件。
4. 运行记录默认位于 `~/.local/state/xhs-luxury-order`，也可通过 `stateDir` 或 `XHS_STATE_DIR` 指定。所有调用方共用同一运行目录；记录必须留在安装包之外。
5. 程序逐单推进，一次调用可以完成本批多个动作。失败、待对账、未接单只影响该单，继续其他独立订单。不要把单步返回、批次结束或页面可打开写成全部成功。

## 防重与恢复

- 内部已有任务 ID：直接核对该任务的达人、广告主及归属，不要求采用新命名规则。
- 无任务 ID：以固定合作名称加达人 ID 唯一匹配；唯一记录只回填，多条或证据不足不猜选，零条且无未决动作才创建。
- 最终创建、回填和付款前，程序先原子保存未决标记。点击报错或进程中断后只读对账；暂未查到结果不能解除标记或重试。
- 原批次记录或订单记录缺失时，不删除记录、换目录或新建批次来绕过。跨电脑恢复必须同时迁移授权及订单记录，停用旧电脑执行器；本轮未验证多电脑并行执行。
- 已付款、已完成、已关闭分别报告，禁止再次付款。禁止点击“取消合作”。

## 业务检查

业务范围、主体、模板、日期、双 SPU、协商价格、保留期和精确核价规则见现行业务规则。付款前重新读取当前同单事实，并将弹窗金额与总额核对；不以历史结果代替当前证据。购物车或表单混入其他达人时报告该单异常，不删除他人的条目。

已有商务角色时自动切换并回读。登录、验证码、风控或确实缺少角色／访问权限时才报告需本人处理；普通技术异常自动恢复，耗尽后如实报告。

## 结果

逐单返回 `WAITING_ACCEPTANCE`、`READY_FOR_PAYMENT`、`PAID`、`COMPLETED`、`CLOSED`、`SKIPPED`、`FAILED`、`RECONCILE_REQUIRED` 或 `NEEDS_USER`。开发走查使用 `preview:true`，返回 `PREVIEW_READY`，停在最终动作前；走查批次不能升级成真实执行批次。

最终报告下单及回填结果、已付／已完成、失败或跳过、待接单、待对账和本人处理事项。`phaseComplete` 只说明本能力是否结束，`paymentComplete` 才表示所有所选订单均已付款或完成。候选包、提交前走查、真实业务验收及同事稳定使用分别判断。
