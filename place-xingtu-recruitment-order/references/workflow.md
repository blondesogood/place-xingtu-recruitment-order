# 招募流程

## 订单号快速路径

1. `prepare` 纯解析 `orderLocators`，去重并保留用户顺序。
2. `run` 才自动创建或复用 Ego Lite 隔离任务空间，每批只确认一次“商务”角色。
3. 在内部订单搜索框用控件清除按钮清空旧值，再输入完整订单号。不核验搜索框回显；只以表格单元格中完整订单号严格唯一匹配为准，随后保存快照、活动绑定和订单锁。
4. 先在“全部报名达人”查找，再在“高价值未报名达人”查找；两个合法来源都不存在时返回 `CREATOR_NOT_ELIGIBLE_IN_ACTIVITY`，该单零写入并继续下一单。
5. 打开下单页并写入上海当月最后一天；日期必须从输入框 `.value` 重读。
6. 做一次提交前轻复核，只点击一次“立即下单”。
7. 星图交付搜索固定为“清空→填入完整达人 ID→派发原生 input/change/key 事件”。提交后最长 90 秒查询唯一星图任务；超时返回 `TASK_RESULT_PENDING`，禁止重提。取得任务 ID 后回填，只点击一次“确认下单”。
8. 精确搜索订单并确认“商务已下单”，输出实际达人和脱敏耗时。

该路径不得调用日期筛选、昵称发现、历史扫描、分页或 delta 扫描。达人名称与订单号冲突时订单号优先，结果报告真实达人。

## 日期范围路径

只有未提供订单号时才进入。输入必须同时包含日期与“全部/数量”，达人名称可选；达人只参与匹配，不决定定位策略。`prepare` 不访问页面，`run` 按以下固定规则选择并持久化本批策略：

- `TABLE_FIRST`：单日且明确处理 1–3 单。关闭遗留抽屉、清空订单号搜索与遗留筛选，只读当前页并横向滚动到达人、平台、任务类型、状态、创建时间列。按日期、抖音、招募、待商务下单和可选达人判断；够数后立即冻结，不扫下一页。
- `FILTER_FIRST`：“全部”、4 单及以上或日期范围超过一天。打开筛选抽屉并重置，精确设置抖音、自定义日期、待商务下单和招募；应用后重读 4 个生效标签，再遍历筛选后的分页。

`TABLE_FIRST` 在当前页数量不足、日期覆盖不能证明、字段不可可靠读取，或指定达人不能证明昵称只对应一个达人 ID 时，只允许升级一次 `FILTER_FIRST`。升级原因和当前策略写入日期发现状态；恢复时不再重跑直读。多个同名达人 ID 仍停止，不猜测。

内部平台目前可能在已提交精确自定义日期后返回相邻日期；执行器仍真实应用并核对 4 个筛选条件，同时对每个分页的创建时间做本地精确日期复核，只有日期范围内的订单可被冻结。指定数量成功后不重复发现；仅当已冻结订单失效才按相同策略找替补。“全部”模式使用筛选后的增量查询，并以最终零结果确认完成。

## 当前操作恢复

- Ego 语义定位失败：截取当前页面，只对当前非状态性操作做一次视觉辅助定位。
- Ego 控制中断或用户接管：交还同一任务空间；用户明确继续后调用 `resume` 接管并从当前业务阶段运行。
- 旧 rc.7/rc.8 状态与锁：继续读取；旧 Chrome 层级只用于兼容记录，不再触发 Chrome。
- 已生成星图任务：只恢复内部回填；已写字段未确认：只重读字段后确认。
- 状态性动作已有 `DISPATCHING` 记录：只查询结果；不能证明未发生时暂停，绝不重复派发。

多单按用户输入顺序串行。订单已完成、状态不符合、不存在或明确单笔业务错误可继续；写入结果、页面身份、账号、订单/达人/金额/活动绑定不明时暂停整批。
